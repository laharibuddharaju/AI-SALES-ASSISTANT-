AI-Powered Sales Assistant:
Intelligent Lead Management with NLP,
Vector Memory, and CRM Integration

A Full-Stack Approach to Conversational Lead Management
Department of Computer Science & Engineering
March 2026
Abstract
Sales teams spend a significant portion of their time on manual data entry, lead tracking, and CRM updates — tasks that are repetitive, error-prone, and time-consuming. This paper presents an AI-Powered Sales Assistant: a web-based system that enables sales representatives to manage leads through natural language conversations. The system leverages OpenAI GPT-4o-mini for intent classification and entity extraction, ChromaDB / SQLite FTS5 for contextual vector memory, and the HubSpot CRM API for real-time contact synchronization. A human-in-the-loop approval mechanism ensures that critical operations (such as deletions) require explicit confirmation before execution. The architecture follows a clean separation of concerns — FastAPI backend, React.js frontend — and is containerised via Docker for production readiness.

Keywords: Natural Language Processing, Intent Classification, CRM Automation, Human-in-the-Loop, Vector Database, FastAPI, React.js

1. Introduction

1.1 Problem Statement

Modern B2B sales pipelines involve managing hundreds of leads across multiple tools. Key challenges include:

  • Manual CRM entry wastes productive selling time
  • Context loss between conversations and CRM records
  • No intelligent assistance during lead qualification
  • Slow approval workflows for sensitive actions like deletions

1.2 Motivation

The rise of conversational AI (e.g., ChatGPT) has demonstrated that natural language is a powerful interface for structured tasks. Applying this to sales operations can:

  • Reduce lead entry time from minutes to seconds
  • Ensure CRM is always up-to-date
  • Give sales reps an AI "copilot" that understands sales intent

1.3 Objectives

  1. Build a conversational interface for full CRUD operations on leads
  2. Classify user intent using LLMs with a regex fallback
  3. Synchronise all changes to HubSpot CRM automatically
  4. Implement a human approval gate for destructive operations
  5. Maintain conversational memory using vector embeddings

4. Methodology

4.1 Intent Classification Pipeline

The system uses a two-stage classification pipeline:

Stage 1 — LLM Classification (Primary)

  • User message is sent to GPT-4o-mini with a structured system prompt
  • Response is constrained to JSON format using response_format: json_object
  • Returns: intent + entities (email, name, phone, company, status, deal_value)

Supported Intents: create_lead · update_lead · delete_lead · show_leads · create_deal · schedule_follow_up · unknown

Stage 2 — Regex Fallback (when no API key)

  • Pattern matches keywords like "create", "delete", "update", "show"
  • Extracts email via regex: \S+@\S+\.\S+
  • Ensures the system is fully functional without an OpenAI key

Entity Merging: LLM and regex entities are merged — regex fills gaps the LLM may miss for structured data like phone numbers and emails.

4.2 Action Execution Flow

User Message
    → classify_with_llm()       # Determine intent + extract entities
    → extract_entities()        # Regex extraction (backup)
    → merge_entities()          # Combine both sources
    → execute_action()
          → persist Conversation (DB)
          → store_message (VectorDB)
          → requires_approval?
                YES → create PendingApproval, return "pending"
                NO  → execute CRUD on Lead
                      → sync with HubSpot CRM
                      → return result

4.3 Human-in-the-Loop Approval

Certain intents are flagged as high-risk:

  • delete_lead — permanent data loss
  • apply_discount — financial impact

When triggered via chat:

  1. A PendingApproval record is created in the database
  2. The chat returns a "pending" response to the user
  3. An admin reviews the action in the Approvals Dashboard
  4. On approval, the action is re-executed with bypass_approval=True

This design prevents accidental or unauthorised destructive operations.

4.4 Vector Memory

BackendTechnologySearch Type
PrimaryChromaDB (cosine similarity)Semantic similarity
FallbackSQLite FTS5 (Porter stemmer)Full-text keyword
DisabledNo-opReturns empty list

Messages are stored per user_id. When an AI response is generated, similar past messages are retrieved to provide contextual continuity across sessions.

4.5 CRM Synchronisation (HubSpot)

Every create_lead and update_lead operation triggers a HubSpot API call:

  • Create: POST /crm/v3/objects/contacts
  • Update: Search by email → PATCH /crm/v3/objects/contacts/{id}
  • Bulk Sync: POST /leads/sync iterates all leads, upserts to HubSpot

If HUBSPOT_API_KEY is not set, a graceful warning is logged and the operation continues locally — ensuring the system functions in dev/offline environments.

8. Conclusion

This paper presented a full-stack AI Sales Assistant that bridges the gap between conversational AI and structured business process automation. By combining:

  • LLM-powered intent classification for natural language interaction
  • Automated CRM synchronisation to eliminate manual data entry
  • Human-in-the-loop approval gates for safe operation
  • Vector memory for persistent conversational context

...the system delivers a practical, production-ready tool that meaningfully reduces the administrative burden on sales teams. The dual-backend approach (LLM primary, regex fallback) ensures the system is resilient and functional across deployment environments with or without an OpenAI API key.

The open-source, Dockerised architecture makes it easily extensible and deployable, positioning it as a foundation for intelligent enterprise sales tooling.
